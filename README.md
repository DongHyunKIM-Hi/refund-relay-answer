# 1단계 — 정상 경로

> [!NOTE]
> **환불 요청 중계 서버 과제의 모범 답안입니다.** 정답은 하나가 아니며, 이 코드는 좋은 구현의 한 예시입니다.
> 단계는 커밋으로 나뉘어 있습니다: `step1`(정상 경로) → `step2`(예외 처리) → `step3`(최종). `git checkout`으로 오갑니다.


과제 1(환불 요청 중계 서버) 정답 코드를 세 단계로 나눈 것 중 첫 번째입니다.
**설계한 흐름이 실제로 도는지만** 확인합니다.

## 만드는 것

- `POST /api/v1/refunds` — 받은 요청을 저장하고 바로 **202**를 응답합니다. 결제대행사를 기다리지 않습니다.
- `GET /api/v1/refunds/{refundId}` — 저장된 건의 현재 상태를 보여 줍니다.
- `RefundWorker` — 0.3초마다 `ACCEPTED` 건을 꺼내 결제대행사를 **한 번** 호출합니다. 성공이면 `COMPLETED`, 아니면 `FAILED`.

## 일부러 하지 않는 것

| 항목 | 지금 | 어디서 채우나 |
|---|---|---|
| 입력 검증(400) | 없음 | 2단계 |
| 중복 요청(200) / 충돌(409) | 없음 | 2단계 |
| 환불 한도(422, `REJECTED`) | 없음 | 2단계 |
| 조회 404, 목록 조회 | 없음 | 2단계 |
| 응답 대기 시간(타임아웃) | 없음 | 2단계 |
| 재시도(최대 4회) | 없음 | 2단계 |
| 같은 주문 순서 처리 | 없음 | 3단계 |
| 동시 요청 안전성(주문 단위 락, DB 유일 제약) | 없음 | 3단계 |

코드 안에서는 각 클래스 맨 위 주석에 "이 단계에서 일부러 하지 않는 것"과 "왜 다음 단계가 필요한지"를 적어 두었습니다.

## 실행

```bash
# 가상 결제대행사
docker run -p 9090:9090 ghcr.io/donghyunkim-hi/pg-mock:1.1.1

# 환불 서버
./gradlew bootRun
```

- 결제대행사 주소는 환경변수 `PG_BASE_URL`로 바꿀 수 있습니다. (기본값 `http://localhost:9090`)
- 단계 전체 설명과 실측 결과는 `docs/stages.md`에 있습니다.
